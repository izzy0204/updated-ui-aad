## 2) Summary
- **Summary:** Tandem Browser is an open-source, local-first Electron browser for AI agents that integrates the AI directly into the user's real browser session. It allows AI agents to share tabs, cookies, and DOM, enabling them to operate on existing websites without per-site APIs or RPA. The system is designed for human-AI co-browsing, where the AI can read the accessibility tree, watch the network, rewrite UI, and pause to ask for human assistance when encountering CAPTCHAs, judgment calls, or unclear forms. It operates on the user's machine with no cloud backend and features an 8-layer security perimeter between web content and the agent layer.

## 3) Intended Use
- **Medical Purpose:** Tandem Browser is intended for users who want to integrate AI agents directly into their daily browsing experience, enabling them to automate web tasks, rewrite live UI, and gather information from websites in a shared human-AI workspace. The workflow involves the AI agent operating within the user's browser, seeing the same DOM, network requests, and accessibility tree. The agent can perform tasks like filling forms, navigating sites, and injecting userscripts. When the agent encounters ambiguity, CAPTCHAs, or risky actions, it pauses and requests human input, allowing for a continuous co-driving experience where the human can intervene or adapt the agent's actions.
- **Acceptable Input:** For Tandem Diabetes Care products (Control-IQ+ technology): Input data comes from integrated continuous glucose monitors (iCGM) readings. For Tandem Engine/Browser: Input data for the AI agent comes directly from the user's real browser session, including the accessibility tree, the rendered DOM, live network requests, console output, DevTools, and user input (clicks, types, commands, responses to prompts). It can also accept input from external applications or custom clients connected via MCP or HTTP API. For Tandem Diabetes Care products: Input data is continuous glucose monitoring (CGM) readings (numerical sensor data). Output data is insulin delivery commands (numerical rates and bolus amounts) for subcutaneous delivery. For Tandem Engine/Browser: Input data types include accessibility tree, rendered DOM, network logs, console output (all structured text/code), user interactions (clicks, keyboard input), and commands via MCP or HTTP API. Output data types include automated browser actions, modifications to live UI (e.g., user scripts), extracted page content (text, HTML, links, forms, images), screenshots, and developer tool outputs (logs, network requests, DOM queries). For Tandem Engine/Browser: The system enables coordinated autonomous work, helps AI assistants achieve correct results (for LLMs), assists desktop users with local file tasks, writing, coding, and agent management, and allows server admins to deploy autonomous agents remotely. AI agents can automate tasks on real SaaS platforms, rewrite live UI on any site via userscripts, provide insights beyond pixels (accessibility tree, DOM, network logs), and engage in real co-browsing with human users. It can open tabs, fill forms, log in, cross-reference sources, handle CAPTCHAs (with human assistance), and inject userscripts. For Tandem Diabetes Care products: The output is the subcutaneous delivery of insulin (basal and bolus doses) at variable rates, based on iCGM readings and predicted glucose values, with the goal of managing blood glucose levels for persons with diabetes. For Tandem Engine/Browser: The output includes automated actions within a browser (e.g., filling forms, navigating sites, injecting userscripts), generated text/code (for coding agents), console logs, network requests, DOM queries, screenshots, and structured data extracted from web pages (e.g., prices). ## 5) Mechanism and Development
- **Model Type:** The Tandem Engine is described as a workflow runtime for AI assistants or agents, capable of orchestrating specialized sub-agents. Tandem Browser is a model-agnostic platform designed to host various AI agents (e.g., LLMs) within a browser environment. Tandem Engine is an engine-owned workflow runtime for coordinated autonomous work, designed to scale beyond chat-first AI assistants and operate in multiple highly-concurrent configurations. It supports AI assistants or agents for local file tasks, writing, coding, or managing agents. It can be deployed to a VPS or headless server for remote access to autonomous agents. Tandem Browser is an open-source, local-first Electron browser for AI agents where the AI operates within the user's real browser session, sharing tabs, cookies, and DOM. It works by interpreting the accessibility tree, rendered DOM, live network requests, and DevTools, enabling agents to operate on existing websites without per-site APIs or RPA rigs. It features co-browsing capabilities, human-in-the-loop for judgment calls (e.g., CAPTCHAs), and an 8-layer security perimeter between web content and the agent layer, including prompt injection defense.
- **Training Data:** Tandem Browser is a model-agnostic platform that enables AI agents to operate within a real browser session. It does not have its own training data in the traditional sense of an AI model. Instead, it works with any connected AI agent that speaks Model Context Protocol (MCP) or HTTP, such as Claude, GPT, Gemini, OpenClaw, local Ollama models, LM Studio, or custom scripts. The capability resides in the connected AI model, not in Tandem Browser itself, which provides the browser environment for these agents. [Dataset](Not specified)
- **Model Development & Validation:** Not specified [Publication](Beck RW, et al. [7] Diabetes Technol Ther. [7] 2023;25(5):329-342. [7])
- **Clinical Trial:** A study was conducted using a t:slim X2 insulin pump with Control-IQ technology and Dexcom G6 sensor, referenced as: Beck RW, et al. Diabetes Technol Ther. 2023;25(5):329-342. This appears to be a clinical evaluation or trial for the Tandem Diabetes Care product.
- **Performance:** For Tandem Diabetes Care products, user testimonials indicate improved A1c and reduced instances of waking up with lows, suggesting the system acts as a 'safety net'. For Tandem Browser, the security pipeline incorporates an 811K+ entry blocklist, YARA-style threat rules, AST fingerprinting, Shannon entropy detection, a confidence-weighted pipeline, and 51 automated tests to achieve its safety and reliability goals. The system provides 257 tools via MCP and over 300 HTTP API endpoints. For Tandem Diabetes Care products, anecdotal evidence from users suggests that the automated insulin delivery systems (Tandem Mobi, t:slim X2 with Control-IQ+ technology) contribute to better glucose management, including improved A1c levels and prevention of hypoglycemic events, enhancing user safety and peace of mind. For Tandem Browser, the multi-layered security architecture (8 layers including NetworkShield, OutboundGuard, ContentAnalyzer, ScriptGuard, BehaviorMonitor, Gatekeeper AI, EvolutionEngine, and PromptInjection defense) is interpreted as a core architectural feature designed to protect the AI agent and user data from malicious web content and prompt injection attacks, ensuring a secure and reliable co-browsing environment for human and AI agents.
